# Host on Vercel Hobby (free) + free backend services

Vercel’s free (Hobby) plan hosts the **Next.js web app only**. This monorepo also needs:

| Piece | Free option | Why |
|-------|-------------|-----|
| Web UI | **Vercel Hobby** | Next.js |
| API (Express) | **Render** free web service | Long-running Node server |
| Worker (BullMQ) | Skip on free / paid Render later | Digests & SLA jobs — not on Free plan |
| Postgres | **Neon** free | Prisma `DATABASE_URL` |
| Redis | **Upstash** free | Health checks (+ worker if paid) |
| File uploads (optional) | Cloudflare R2 / skip | S3-compatible; app works without it |

Repo: https://github.com/Aneenaanu321/P11_Sales-Operations-Managing-Dashboard

---

## 1. Neon (Postgres)

1. Sign up at [neon.tech](https://neon.tech) → create a project.
2. Copy the connection string (`postgresql://…?sslmode=require`).
3. You’ll paste this as `DATABASE_URL` on Render.

---

## 2. Upstash (Redis)

1. Sign up at [upstash.com](https://upstash.com) → create a Redis database.
2. Copy the **Redis URL** (`rediss://…`).
3. Paste as `REDIS_URL` on Render (API + worker).

---

## 3. Render (API only on Free)

1. Go to [render.com](https://render.com) → **New** → **Blueprint**.
2. Connect the GitHub repo above (branch `main`).
3. Render reads `render.yaml` and proposes **`rfidcore-api`** only (workers are not on Free).
4. Fill secrets when prompted:

| Env var | Value |
|---------|--------|
| `DATABASE_URL` | Neon URL |
| `REDIS_URL` | Upstash URL (`rediss://…`) |
| `CORS_ORIGIN` | Your Vercel URL, e.g. `https://your-app.vercel.app` (set after Vercel deploy; `http://localhost:3000` is OK temporarily) |
| `JWT_ACCESS_SECRET` | Auto-generated by Render, or `openssl rand -hex 32` |
| `JWT_REFRESH_SECRET` | Different random 32+ char secret |

5. Deploy. Note the API URL, e.g. `https://rfidcore-api.onrender.com`.

6. **Migrate + seed (Free plan has no Shell)**

Migrations run automatically on each deploy via `preDeployCommand` in `render.yaml`.

Seed demo data **once from your laptop** (uses Neon directly — no Render Shell):

```bash
export DATABASE_URL='postgresql://USER:PASS@HOST/neondb?sslmode=require'
npm run prisma:deploy -w apps/api
npm run prisma:seed -w apps/api
```

Demo login after seed: `admin@ibtechintl.com` / `Password123!`  
Coordinator: `coordinator@ibtechintl.com` / `Password123!`

> Free Render services **spin down after idle**. First request after sleep can take ~30–60s.  
> Scheduled digests / SLA breach jobs need a paid worker later — the UI works without them.

## 4. Vercel (web)

1. Go to [vercel.com](https://vercel.com) → **Add New Project** → import  
   `Aneenaanu321/P11_Sales-Operations-Managing-Dashboard`.
2. Configure:

| Setting | Value |
|---------|--------|
| Framework Preset | Next.js |
| Root Directory | leave **repository root** (uses root `vercel.json`) |
| Build Command | `npm run build -w @rfidcore/web` (from `vercel.json`) |
| Install Command | `npm install` |

3. Environment variables:

| Name | Value |
|------|--------|
| `NEXT_PUBLIC_API_URL` | `https://rfidcore-api.onrender.com/api/v1` (your Render URL + `/api/v1`) |

4. Deploy. Copy the production URL (`https://….vercel.app`).

5. Go back to Render → API (+ worker) → set:

```text
CORS_ORIGIN=https://your-app.vercel.app
```

Redeploy API so CORS + cookies pick up the Vercel origin.

---

## 5. Smoke test

1. Open the Vercel URL → `/login`.
2. Sign in with a seeded demo user.
3. Confirm Dashboard loads (sidebar + KPIs).
4. If login fails with CORS errors: check `CORS_ORIGIN` matches the Vercel URL **exactly** (no trailing slash).

---

## Local vs production cookies

Production sets refresh cookies as `SameSite=None; Secure` so the browser sends them from Vercel → Render. Access tokens stay in a JS cookie on the Vercel domain (Bearer header).

---

## Limits of the free stack

- Render free web: cold starts; 750 hrs/month shared.
- Neon / Upstash: storage & connection caps — fine for demos.
- No MinIO by default → file attachments may fail until you add R2/S3 env vars.
- AI Assistant needs `ANTHROPIC_API_KEY` on the API service.
- Email needs SMTP vars; otherwise notifications stay in-app only.

For a more reliable (still low-cost) setup later: upgrade Render to a paid starter, or use Railway / Fly for always-on API.
